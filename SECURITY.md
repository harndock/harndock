# Security Policy

## Reporting a vulnerability

Do not disclose suspected vulnerabilities in a public issue, discussion, or pull request.

Use the repository's private GitHub security advisory reporting flow. Include the affected version or commit, reproduction steps, impact, and any suggested mitigation. Avoid attaching real credentials, private keys, access tokens, personal data, or production database contents.

If private vulnerability reporting is unavailable, open a public issue containing no exploit details or sensitive data and ask a maintainer to establish a private communication channel.

## Supported versions

Harndock has not published a stable signed release. Security fixes currently target the latest commit on the default branch. A version support table will be added when stable releases begin.

## Scope

Reports concerning the Harndock desktop host, mobile client, product packages, runtime assembly, or update boundaries belong here. Vulnerabilities that reproduce only in DeepSeek Harness should also be reported to the upstream project.
