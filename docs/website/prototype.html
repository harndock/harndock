Three surfaces

每个设备，都有自己的角色。

不把同一套界面硬塞到所有屏幕里。harndock 让每个端只做它最擅长的事。

01 / DESKTOP执行源

本机 Desktop

一个可安装、可恢复的桌面宿主，承载本地 Harness Runtime 和 Web GUI。

  • 启动、停止与健康检查
  • Runtime 版本与 Profile 管理
  • 本地会话与插件工作流
02 / MOBILE随身端

移动 Mobile

React Native Viewer / Controller，随时查看进度，必要时发送指令或完成审批。

  • Session 时间线与历史补发
  • 实时流、断线重连与离线态
  • Prompt、停止与一次性审批
03 / GATEWAY连接层

远程 Gateway

面向当前账号的独立管理页，集中处理设备、Runtime、Token 和连接诊断。

  • 设备与 PC Runtime 状态
  • Pairing、Token 与会话撤销
  • 隐私设置与流诊断摘要
How it connects

执行在本机，控制在手上。

Gateway 负责认证、转发和协调，不替代你的 PC Harness Runtime。每一层的边界都清楚可见。

01 / DESKTOP

PC Harness Runtime

模型、工具、文件与 Session 的唯一执行源，保持在你的本机。

02 / GATEWAY

认证与同步

通过出站 TLS 连接协调设备、历史事件和命令队列，不要求开放家庭端口。

03 / MOBILE

Viewer / Controller

在手机上查看同源时间线，需要时发送控制命令并接收明确的状态反馈。

Questions

开始之前，先了解这些。

Desktop 承载本机 Harness Runtime，是模型、工具、文件和 Session 的执行源；Gateway 负责认证、转发、存储和协调；Mobile 作为 Viewer / Controller 查看并控制同一份 Session。
不会。Gateway 是连接层，不运行你的模型和工具。PC Harness Runtime 仍在本机执行，Gateway 只同步必要的事件和命令状态。
移动端支持登录、Session 查看、实时事件、历史补发、发送 prompt、停止任务和一次性工具审批；复杂编辑、附件和跨 PC 迁移不在首版范围内。
Host plugin 在本机 Runtime 中运行，安装等同于允许本机执行代码。Gateway 只保存凭据摘要和元数据；原始 access token 仅在签发成功时展示一次。
